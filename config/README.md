# Configuration

Values are supplied at build time with `--dart-define-from-file`. Nothing here is
read at runtime from disk, and no configuration file ships inside the app bundle.

## Setup

```bash
cp config/example.json config/dev.json
# fill in the values, then:
flutter run --dart-define-from-file=config/dev.json
```

`dev.json` and `prod.json` are gitignored. `example.json` is committed and lists
every key the app expects, so a fresh clone knows what to supply.

## Why not a `.env` file

A `.env` bundled as a Flutter asset ships inside the APK and can be read with
`unzip`. It offers the feeling of a secret without the property of one.
`--dart-define` compiles values into the binary instead — no file to leak, and no
asset for anyone to extract.

That is a distribution argument, not a security one: **every key below is
publishable by design.** They are kept out of git because they are
per-environment and because rotating a committed key is painful, not because
exposure would be a breach.

The genuine secrets — Stripe secret key, Supabase service-role key, database
password — live on the backend and never appear in this repository.

## Keys

| Key | What it is | Where it comes from |
|---|---|---|
| `SUPABASE_URL` | Project URL for GoTrue auth | Supabase dashboard |
| `SUPABASE_ANON_KEY` | Publishable anon key. Row-level security is what protects data, not this key's secrecy | Supabase dashboard |
| `STRIPE_PUBLISHABLE_KEY` | `pk_test_…` in test mode, `pk_live_…` at release. Only ever the publishable half | Stripe dashboard |
| `SENTRY_DSN` | Crash reporting endpoint. Write-only by design | Sentry project settings |
| `API_BASE_URL` | Ride service. Defaults to production | — |

Read in Dart with `String.fromEnvironment`, which is compile-time constant:

```dart
const supabaseUrl = String.fromEnvironment('SUPABASE_URL');
```

## The two that cannot use `--dart-define`

The Google Maps SDK reads its key from native platform configuration before any
Dart runs, so it cannot come from `--dart-define`.

**Android** — `android/local.properties` (gitignored):
```properties
MAPS_API_KEY=AIza...
```
Gradle injects it into the manifest placeholder.

**iOS** — a gitignored `.xcconfig`, or `AppDelegate.swift`.

Restrict each key in the Google Cloud console to its bundle ID and to the Maps
SDK alone. An unrestricted Maps key is billable by anyone who finds it — which is
the one place in this list where exposure genuinely costs money.

## Firebase

`google-services.json` (Android) and `GoogleService-Info.plist` (iOS) are
generated by the Firebase console and gitignored. Download them per platform and
drop them in place; they are not managed here.

## Switching to live Stripe

Change `STRIPE_PUBLISHABLE_KEY` to the `pk_live_…` value in `prod.json`. No code
change — the backend must be pointed at live mode in the same release.
